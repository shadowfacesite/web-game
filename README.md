# ЗАТОН

Веб-хоррор от первого лица. Дом 24 × 16 м, четыре уровня, пятнадцать помещений.

Сейчас в работе **кит шаблонов**: карта, на которой лежат готовые детали для
сборки уровней — стены, двери, окна, мебель, реквизит. Каждую можно двигать,
вращать по трём осям и менять в размерах.

---

## Запуск

```
npm install
npm run dev
```

Открывается редактор. Три режима переключаются кнопками наверху:

| Режим     | Что показывает |
|-----------|----------------|
| Витрина   | все 71 шаблон, разложенные по группам, с подписями |
| Пусто     | сетка, ростовой эталон и метровый куб — сюда ставят своё |
| Дом       | дом, собранный из `spec/house-map.json` |

## Управление

| Клавиша | Что делает |
|---------|------------|
| ЛКМ по предмету | выделить |
| W / 1 | гизмо перемещения — стрелки по X, Y, Z |
| E / 2 | гизмо вращения — кольца по X, Y, Z |
| R / 3 | гизмо масштаба — кубики по X, Y, Z |
| D | дублировать |
| Del | удалить |
| Z | шаг назад |
| Esc | снять выделение |
| Tab | пройтись пешком с высоты глаз (1.65 м) |

Шаг привязки и шаг угла выбираются в верхней панели. По умолчанию 25 см и 15°.
Кнопка «Оси мира / Оси предмета» переключает, в каких осях крутить.

Перетащи `.glb` из Blender прямо на окно — модель загрузится, а в сообщении
внизу появятся её габариты и замечания, если что-то не так с масштабом или осями.

## Проверки

```
npm run check      всё сразу
npm run kit        только шаблоны
npm run kit:list   таблица шаблонов с габаритами
npm run blockout   объём дома
npm run validate   планировка
```

`npm run kit` гоняет каждый шаблон на **705 наборах значений**: каждый параметр
по очереди в минимум и в максимум, потом все сразу. Именно на краях диапазона
шаблоны и ломаются, и именно там проверка их и поймала:

- полотно одностворчатой двери строилось от петли наружу проёма;
- марш лестницы крутился вокруг своего нижнего края, а не вокруг себя;
- проём мог уехать за край стены, и простенок вырождался в нулевую грань;
- у раковины пьедестал не доходил до пола;
- бра с коротким кронштейном загоняло плафон внутрь стены.

Проверки идут до сборки: сломанный шаблон не попадает в игру.

**Но зелёные тесты этап не закрывают.** Этап закрывает скриншот. Прошлый заход
имел 201 зелёную проверку и был визуально сломан.

## Blender

```
npm run blender
```

Кладёт в `export/`:

| Файл | Что внутри |
|------|-----------|
| `house.obj` | дом целиком, по объекту на уровень |
| `kit.obj` | все шаблоны рядами |
| `zaton.mtl` | служебные цвета к обоим |

`File → Import → Wavefront (.obj)`. Настройки менять не нужно: единицы метры,
ось Y вверх — совпадает с китом.

Обратно — экспорт glTF 2.0 (`.glb`) и перетаскивание файла на окно редактора.
Галку «+Y Up» не снимай, масштаб перед экспортом применяй (`Ctrl+A → Scale`).

### Одна планировка

`spec/house-map.json` — единственный источник правды о планировке. Из него растут
дом, коллизии, чертёж и валидатор. `house.obj` — его отпечаток: поменял карту,
перевыгрузил, подложка обновилась.

Как только стены начнут двигать в Blender и не переносить это в карту,
планировок станет две. Ровно на этом умер прошлый заход: чертёж и игра стали
двумя разными домами, и никто не помнил, какой настоящий.

## Устройство

```
spec/house-map.json    планировка: комнаты, двери, связи, стадии
src/world/geometry.ts  карта → объём и коллизии. Без импортов движка
src/kit/core.ts        язык описания шаблонов: примитивы, параметры, части
src/kit/parts.ts       общие узлы: ножки, рамы, корпуса, ручки
src/kit/lib/*.ts       сами шаблоны, по файлу на группу
src/kit/catalog.ts     каталог и расстановка как данные
src/kit/obj.ts         выгрузка в OBJ
src/engine/*.ts        единственное место стыка с Babylon.js
src/editor/*.ts        выделение, гизмо, панели, режимы карты
tools/*.mjs            проверки и выгрузка, работают без браузера
```

Всё, что можно посчитать без движка, посчитано без движка. Не из чистоплюйства:
то, что считается без браузера, я могу проверить сам, а картинку — нет.
Побочная выгода уже окупилась — при переезде с three.js на Babylon.js
`geometry.ts`, карта и валидаторы переехали без единой правки.

## Движок

**Babylon.js.** Выбран из-за `GizmoManager`: стрелки перемещения, кольца
вращения и кубики масштаба по X, Y, Z встроены в движок. В three.js это
пришлось бы собирать руками, а собранное руками ломается на краях.

WebGL — не альтернатива движку: это графический интерфейс браузера к видеокарте,
и Babylon рисует через него. То есть проект и так на WebGL.

Правосторонняя система координат включена явно (`useRightHandedSystem = true`).
Babylon по умолчанию левосторонний, и это единственное, чем он расходится с
glTF, Blender и three.js. Оставить как есть — получить зеркальный дом.

## Новый шаблон

Двадцать строк в `src/kit/lib/`:

```ts
{
  id: "verstak",
  name: "Верстак",
  group: "furniture",
  mount: "floor",
  note: "Столешница на тумбах, с тисками.",
  params: [P("w", "Длина", 1.6, 0.8, 3, 0.05)],
  build: (p) => ({ prims: [ /* … */ ] }),
}
```

Панель настроек он получит сам — она строится из описания параметров.
`npm run kit` проверит его на всех крайних значениях.

## Ограничения

- Прыжка в игре нет.
- Клетка планировки 0.5 м, всё кратно ей.
- Уровни: подвал −3.0, первый 0.0, второй 3.0, третий 6.0.
- Высота глаз 1.65 м. Дом построен под это число.
